# 🔹 Práctica 2.10 - Network Traceroute Threat Auditor

En los departamentos de Respuesta a Incidentes (*Incident Response*), los analistas forenses deben rastrear las rutas físicas que recorren las conexiones sospechosas. El enrutamiento de red consiste en saltos progresivos entre routers. Si un paquete de datos pasa por un salto que pertenece a una IP de un país bajo embargo o un servidor proxy anónimo conocido, el incidente debe catalogarse inmediatamente como una anomalía de alta severidad.

En esta práctica, programarás un analizador automatizado de trazas de red para determinar la integridad del enrutamiento y auditar la latencia de respuesta de los servidores intermediarios.

---

## 🎯 Objetivos de la Actividad

* Aplicar la función integrada `enumerate()` con el argumento `start=1` para indexar saltos físicos de red de forma pythónica.
* Combinar la iteración sincrónica con `zip()` e indexación con `enumerate()` para analizar métricas multidimensionales en paralelo.
* Implementar lógica de auditoría basada en constantes inmutables para listas negras de IPs y umbrales de latencia.
* Garantizar la encapsulación de variables de estado sin hacer uso de variables globales dentro de las funciones.
* Modularizar el programa siguiendo los estándares de estilo PEP 8 y documentación PEP 257.

---

## 💻 El Reto: Desarrollar el Auditor de Ruta de Red

Tu objetivo es programar un script en Python (`ra2_act10_auditor_ruta.py` / `b2_10_auditor_ruta.py`) que audite un listado de saltos de red, calcule el tiempo transcurrido, verifique la validez de los nodos utilizando un listado de IPs sospechosas y determine en qué posición exacta de la ruta se vulneró la seguridad de los datos.

### 📊 Datos de Entrada de Referencia

Tu script debe definir las siguientes constantes globales e inicializar los casos de prueba para validar el algoritmo:

```python
# Constantes de Seguridad (PEP 8)
IPS_SOSPECHOSAS = ("185.220.101.5", "45.142.120.9", "109.201.154.3")
LIMITE_LATENCIA = 120  # Límite en milisegundos

# Caso de Prueba 1: Ruta Segura (Canal Limpio)
NODOS_RUTA_1 = ["192.168.1.1", "10.0.0.1", "172.16.0.5", "8.8.8.8"]
LATENCIAS_MS_1 = [5, 12, 45, 95]

# Caso de Prueba 2: Ruta Comprometida (Ataque con desvío y retardo)
NODOS_RUTA_2 = ["192.168.0.1", "10.100.1.1", "45.142.120.9", "109.201.154.3", "195.12.5.40"]
LATENCIAS_MS_2 = [15, 30, 240, 110, 310]

```

## 🛠️ Requisitos Funcionales del Programa

### 1. Definición de Constantes de Seguridad (PEP 8)

* Declara la tupla inmutable `IPS_SOSPECHOSAS` con las IPs hostiles: `"185.220.101.5"`, `"45.142.120.9"`, `"109.201.154.3"`.
* Declara la constante entera `LIMITE_LATENCIA = 120` (expresada en milisegundos).

### 2. Modularización mediante Funciones

Deberás programar obligatoriamente la siguiente función equipada con su respectivo **Docstring PEP 257**:

* **`auditar_traceroute(nodos_ruta, latencias_ms)`**:
* **Parámetros:** Recibe la lista de nombres/IPs de los saltos de red (`nodos_ruta`) y la lista de latencias en milisegundos (`latencias_ms`).
* **Sincronización e Indexación:** Recorre simultáneamente ambas listas utilizando `zip()`. Para indexar los saltos físicamente comenzando en el número **1**, debes envolver el iterador resultante utilizando `enumerate(..., start=1)`.
* **Evaluación de Seguridad:** En cada vuelta del bucle realiza dos verificaciones:
1. Si la IP del nodo actual pertenece a `IPS_SOSPECHOSAS`, marca la ruta como comprometida y guarda el número de salto exacto.
2. Si la latencia del salto supera `LIMITE_LATENCIA`, registra que ese salto sufrió un retraso anómalo.


* **Salida de Consola:** Imprime de forma ordenada el análisis de cada salto en pantalla utilizando f-strings, destacando visualmente si el nodo es normal, si superó el límite de latencia o si pertenece a la lista negra.
* **Valor de Retorno:** Devuelve una tupla con tres elementos:
1. Un booleano indicando si la ruta es segura (`True` si no contiene IPs sospechosas, `False` si contiene al menos una).
2. El número del primer salto comprometido (un entero `int` o `None` si no hubo incidentes).
3. Una lista de tuplas con el formato `(salto_id, ip_nodo)` que contenga exclusivamente los saltos que registraron latencias superiores a `LIMITE_LATENCIA`.





### 3. Programa Principal e Interacción (`if __name__ == "__main__":`)

1. Inicializa las constantes globales y las listas de prueba para la **Ruta Segura** y la **Ruta Comprometida**.
2. Invoca a la función `auditar_traceroute()` pasándole los datos de la Ruta Segura, captura sus tres valores devueltos y muestra el informe resumido para el analista del SOC.
3. Invoca a la función `auditar_traceroute()` pasándole los datos de la Ruta Comprometida, captura sus tres valores devueltos y muestra el informe de alerta correspondiente.

## 📋 Restricciones y Estilo de Programación

* **Sin Variables Globales Sucias:** Queda estrictamente prohibido modificar o consultar variables globales dentro de la función auditora para mantener estados. Toda la lógica debe trabajar sobre los parámetros recibidos y retornar los resultados mediante `return`.
* **Uso obligatorio de `enumerate()`:** El reporte debe indexar los saltos lógicos empezando en 1 haciendo uso del argumento opcional `start=1`. Queda totalmente prohibido el uso de contadores manuales (`i = 0`, `i += 1`) o la iteración indirecta mediante `range(len())`.
* **Documentación PEP 257:** La función `auditar_traceroute` debe incluir un **Docstring multilínea** (`"""`) detallando explícitamente su propósito, parámetros recibidos y el tipo de dato de su valor devuelto.
* **Formatos de Salida:** Destaca claramente las IPs sospechosas y los saltos con latencia alta mediante f-strings estructurados para permitir una lectura rápida por parte del operador de guardia.
