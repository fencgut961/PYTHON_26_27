## 🛠️ El Reto: SOC Incident Response Orchestrator (SIEM-Lite)

Trabajas como analista senior de seguridad en el Centro de Operaciones de Seguridad (SOC) de una multinacional tecnológica. Un sofisticado grupo de atacantes está intentando vulnerar la infraestructura de servidores web y bases de datos corporativas.

Tu misión es programar una herramienta de consola interactiva llamada **SOC Incident Response Orchestrator**. Este script procesará ráfagas de telemetría de red cruda en tiempo real, correlacionará logs paralelos de tráfico, clasificará las amenazas de forma computacional mediante comprensiones, mantendrá una base de datos dinámica de amenazas y orquestará las reglas automáticas de mitigación en el cortafuegos (*firewall*).

## 📋 Requisitos Técnicos del Programa

El script principal deberá llamarse `b2_final_orchestrator.py` y deberá estar estructurado en las siguientes fases funcionales obligatorias:

### 1. Variables de Estado Global y Configuración (UD 2.4, 2.5, 2.6)

Define las siguientes variables al inicio del script (fuera de cualquier función):

* `SERVIDORES_CRITICOS` (Tupla inmutable): Contiene los nombres de los hosts que no deben verse interrumpidos bajo ningún concepto: `("srv-db-prod", "srv-auth-core", "srv-gateway-main")`.
* `PUERTOS_SENSIBLES` (Tupla inmutable): Puertos de administración críticos: `(22, 3389, 80, 443)`.
* `blacklist_global` (Lista mutable): Almacenará las direcciones IP confirmadas como amenazas y bloqueadas activamente por el firewall. Inicialízala con una IP sospechosa: `["185.220.101.5"]`.
* `incidentes_activos` (Diccionario mutable): Almacenará el inventario de incidentes en curso bajo la estructura de base de datos local en memoria. Inicialízalo vacío `{}`.

### 2. Flujo de Datos Crudos e Iteración Controlada (UD 2.11)

El cortafuegos central simula un flujo continuo de telemetría mediante un diccionario de prueba. Define esta constante en tu programa principal:

```python
TELEMETRIA_SENSORS = {
    "timestamps": ["10:45:12", "10:45:15", "10:45:18", "10:45:22", "10:45:30"],
    "ips_origen": [
        "192.168.1.105",
        "185.220.101.99",
        "10.0.0.45",
        "185.220.101.99",
        "192.168.1.200",
    ],
    "puertos_destino": [80, 22, 443, 3389, 22],
    "payloads": [
        "GET /index.html",
        "SSH brute-force attempt",
        "GET /api/v1/status",
        "RDP exploit payload",
        "SSH successful login",
    ],
}

```

Debes implementar una función `obtener_siguiente_evento(iteradores_dict)` que reciba un diccionario conteniendo iteradores manuales y, haciendo uso exclusivo de `next(iterador, None)`, devuelva el siguiente paquete de telemetría unificado en una tupla de 4 elementos. Si el flujo se agota, debe retornar `None`.

### 3. Sincronización Forense y Enumeración (UD 2.9, 2.10)

Programa una función `correlacionar_trazas_red()` que:

1. Reciba como parámetros las listas del diccionario de telemetría corporativa.
2. Utilice `zip()` para emparejar de forma segura las marcas de tiempo, IPs, puertos y cargas útiles.
3. Utilice `enumerate()` (comenzando el conteo de incidentes en `1`) para recorrerlos en un único bucle.
4. Imprima por pantalla una tabla formateada de los eventos del analizador.

### 4. Filtrado Avanzado de Amenazas (UD 2.8)

Implementa la función `analizar_patrones_criticos()` que reciba la lista correlacionada de eventos. Haciendo uso obligatorio de **comprensióm de listas con filtrado inline**, debe aislar y retornar en una sola línea de código únicamente las IPs de origen que hayan intentado acceder a un puerto que esté dentro de la tupla global `PUERTOS_SENSIBLES` y que no pertenezcan al rango local de confianza (es decir, aquellas IPs que no empiecen por `"192.168."` ni por `"10."`).

### 5. Orquestación de Mitigación y Base de Datos CRUD (UD 2.2, 2.3, 2.4, 2.7)

Implementa las siguientes funciones de gestión:

* `calcular_score_riesgo(puerto, es_servidor_critico=False)`: Calcula y retorna un entero como puntuación de amenaza. Si el puerto está en `PUERTOS_SENSIBLES`, la base de riesgo es `50` puntos (si no, `10`). Si además el ataque va dirigido a uno de los servidores que coincida con la tupla global `SERVIDORES_CRITICOS`, el riesgo se multiplica por `2`.
* `registrar_bloqueo(ip_atacante)`: Función que añade la IP de forma segura a la lista global `blacklist_global`. Debe evitar duplicados. Requiere el uso correcto de variables globales de escritura.
* `mitigar_amenazas(ips_sospechosas, servidor_destino)`: Recibe la lista de IPs sospechosas aisladas anteriormente y el servidor que está sufriendo la intrusión. Para cada IP:
1. Calcula su score de riesgo invocando a la función correspondiente.
2. Si el score supera los 50 puntos, llama a `registrar_bloqueo()` para banear la IP.
3. Registra la alerta en el diccionario de datos global `incidentes_activos` utilizando un identificador autogenerado (ej. `"INC-1"`, `"INC-2"`...) guardando el host, riesgo, IP y estado del bloqueo.

## 🖥️ Interfaz del Menú de Consola (UD 2.1)

El programa principal debe ejecutar un bucle interactivo permanente `while True` que muestre un menú de administración del SOC mediante `match-case`. Debe tener las siguientes opciones:

```text
=========================================
     SOC INCIDENT ORCHESTRATOR v1.0
=========================================
1. Simular Análisis de Telemetría (zip + enumerate)
2. Ejecutar Filtro SIEM (Comprensiones de Listas)
3. Ejecutar Mitigación Activa en Cortafuegos
4. Mostrar Base de Datos de Incidentes (CRUD)
5. Simular Sensor en Vivo (Iteradores manuales)
6. Salir del Sistema de Defensa
=========================================

```

### Comportamiento Esperado de las Opciones:

* **Opción 1:** Muestra los logs en crudo alineados en columnas ordenadas e indexadas.
* **Opción 2:** Muestra las IPs sospechosas del exterior que han atacado puertos sensibles del sistema.
* **Opción 3:** Solicita al analista el nombre del servidor objetivo (ej. `"srv-db-prod"`) y procesa de forma masiva los bloqueos de IPs sospechosas, mostrando alertas en tiempo real y modificando las variables globales.
* **Opción 4:** Imprime de manera estructurada los incidentes activos registrados y muestra el estado actual de la `blacklist_global` del firewall.
* **Opción 5:** Inicia una simulación interactiva paso a paso donde el analista avanza manualmente por los eventos del cortafuegos de uno en uno pulsando Enter (usando `next()`), deteniéndose de manera controlada sin errores cuando no queden más paquetes.
* **Opción 6:** Termina el bucle de ejecución de forma segura.
