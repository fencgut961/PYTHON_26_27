## 🧱 1. La Sentencia `return` y la Transferencia de Control

En la arquitectura de software, las funciones avanzadas actúan como **transformadores de información**: reciben datos a través de sus parámetros, ejecutan un algoritmo y **devuelven un resultado** al punto exacto del programa donde fueron invocadas.

Para lograr esta transferencia de datos se utiliza la palabra reservada **`return`**, la cual cumple dos funciones críticas e indivisibles:

1. **Finalización inmediata:** Interrumpe la ejecución del cuerpo de la función de forma instantánea. Cualquier instrucción escrita tras la sentencia `return` en el mismo flujo condicional se considera **código inalcanzable** (*unreachable code*).
2. **Devolución del objeto:** Envía el resultado evaluado de vuelta al flujo principal, sustituyendo la invocación de la función por el valor devuelto.

```python
def calcular_experiencia_total(misiones_completadas, xp_por_mision):
    """Calcula la experiencia acumulada procesando los parámetros."""
    xp_total = misiones_completadas * xp_por_mision
    return xp_total  # Concluye la función y entrega el valor numérico


# Invocación: El valor devuelto (1500) se asigna directamente a la variable
experiencia_jugador = calcular_experiencia_total(5, 300)
print(f"XP acumulada: {experiencia_jugador}")  # Imprime: XP acumulada: 1500

```

## 📊 2. Comparativa Fundamental: `print()` vs. `return`

Uno de los errores conceptuales más frecuentes en las etapas iniciales de la programación es confundir la **impresión en consola** con la **devolución de un dato**.

```python
# ❌ FUNCIÓN QUE SOLO IMPRIME (No devuelve nada útil al programa)
def calcular_daño_impreso(base, bono):
    print(base + bono)  # El dato se muestra al usuario pero se destruye en memoria


# ✅ FUNCIÓN QUE DEVUELVE UN DATO (Procesable y reutilizable)
def calcular_daño_retornado(base, bono):
    return base + bono  # El dato se envía al programa

```

| Criterio | Función con `print()` | Función con `return` |
| --- | --- | --- |
| **Destinatario** | El usuario humano (consola de comandos). | El propio programa informático (código). |
| **Reutilización** | **Nula.** El valor se pierde tras renderizarse. | **Alta.** Se puede almacenar en variables o pasarse a otras funciones. |
| **Tipo devuelto** | Devuelve implícitamente `None`. | Devuelve el objeto evaluado (`int`, `float`, `str`, `bool`, etc.). |
| **Encadenamiento** | Imposible usar en expresiones matemáticas. | Permite componer operaciones: `f(x) + g(y)`. |

## ❓ 3. El Tipo de Dato Especial `NoneType` (`None`)

En Python, **toda función devuelve un valor**. Si el desarrollador no incluye explícitamente una cláusula `return`, o escribe la palabra `return` sin acompañarla de ninguna expresión, la función ejecutará de forma automática un **`return None`** implícito al llegar a su última línea.

`None` es un objeto único perteneciente a la clase `NoneType` que representa la **ausencia explícita de valor**.

```python
def registrar_log(mensaje):
    """Imprime un mensaje en consola sin devolver ningún valor."""
    print(f"[LOG]: {mensaje}")


# Al no haber 'return', la variable recibe el objeto 'None'
resultado = registrar_log("Servidor reiniciado")

print(resultado)  # Imprime: None
print(type(resultado))  # Imprime: <class 'NoneType'>

```

> **Uso de `None` como Centinela:** Es habitual utilizar `None` en retornos explícitos para señalar que una operación no pudo completarse con éxito debido a datos de entrada no válidos.

## ⚡ 4. Patrón *Early Return* (Retorno Temprano)

Una función puede incorporar múltiples sentencias `return` dentro de distintas ramas condicionales. Sin embargo, en el momento en que el intérprete alcanza la **primera sentencia `return` activa**, la función finaliza inmediatamente, ignorando las líneas restantes.

El patrón **Early Return** es una técnica de refactorización que evalúa primero los casos de error o condiciones límite (*guard clauses*) y los retorna de inmediato, evitando el anidamiento excesivo de bloques `if-else`.

### ❌ Antipatrón: Anidamiento de código (*Arrow Anti-pattern*)

```python
def validar_nivel_acceso_complejo(nivel, tiene_clave):
    if nivel >= 1:
        if nivel <= 50:
            if tiene_clave:
                resultado = "Acceso Permitido"
            else:
                resultado = "Error: Clave requerida"
        else:
            resultado = "Error: Nivel fuera de rango"
    else:
        resultado = "Error: Nivel inválido"
    return resultado

```

### ✅ Solución: Aplicación de *Early Return*

```python
def validar_nivel_acceso(nivel, tiene_clave):
    """Evalúa los permisos de acceso aplicando cláusulas de guardia."""
    if nivel < 1 or nivel > 50:
        return "Error: Nivel fuera de rango"

    if not tiene_clave:
        return "Error: Clave requerida"

    # Flujo principal sin anidamientos
    return "Acceso Permitido"

```

## 📦 5. Retornos Múltiples (Devolución Empaquetada)

Python permite devolver múltiples valores desde una única función separándolos mediante comas en la sentencia `return`. El intérprete empaqueta automáticamente dichos valores en una tupla, la cual puede **desempaquetarse directamente** en la invocación.

```python
def calcular_metricas_jugador(vida_base, armadura):
    """Calcula y devuelve la vida efectiva y la tasa de mitigación."""
    vida_efectiva = vida_base * 1.5
    mitigacion = armadura * 0.08
    return vida_efectiva, mitigacion  # Devuelve dos valores


# Desempaquetado directo en dos variables independientes
hp_total, def_total = calcular_metricas_jugador(100, 25)

print(f"HP: {hp_total} | Defensa: {def_total}")

```

## 📑 6. Documentación del Retorno (PEP 257)

Cuando una función retorna datos, la especificación **PEP 257** dictamina que debe incluirse una sección explicativa en el **Docstring** especificando la naturaleza del valor devuelto mediante la etiqueta `:return:` o `:returns:`.

```python
def calcular_factor_multiplicador(racha_victorias):
    """Calcula el multiplicador de puntos según la racha de partidas ganadas.

    :param racha_victorias: Número entero de partidas ganadas consecutivamente.
    :return: Factor multiplicador aplicado a los puntos (float).
    """
    if racha_victorias >= 5:
        return 2.0
    elif racha_victorias >= 3:
        return 1.5
    return 1.0

```

El siguiente programa simula el subsistema de tienda de objetos de **SteamArcade**, haciendo uso de funciones puras con retornos de datos y validaciones avanzadas:

```python
"""
Módulo de procesamiento de compras e inventario para SteamArcade.
Demuestra el uso de la cláusula return, Early Return y documentación PEP 257.
"""

# --- CONSTANTES ---
DESCUENTO_VIP = 0.15  # 15% de descuento


# --- FUNCIONES DE CÁLCULO Y NEGOCIO ---
def calcular_precio_final(precio_base, es_vip, impuesto_local=0.21):
    """Calcula el coste total de un producto considerando descuentos y tributos.

    :param precio_base: Importe bruto del objeto (float).

    if precio_base <= 0:
        return -1.0  # Retorno centinela por dato erróneo

    subtotal = precio_base
    if es_vip:
        subtotal -= precio_base * DESCUENTO_VIP

    total_impuestos = subtotal * impuesto_local
    return round(subtotal + total_impuestos, 2)


def verificar_saldo_suficiente(creditos_usuario, coste_total):
    """Comprueba si el usuario puede costear la transacción.

    :return: True si el saldo es suficiente, False en caso contrario.
    """
    return creditos_usuario >= coste_total


# --- PUNTO DE ENTRADA PRINCIPAL ---
saldo_jugador = 150.0

usuario_es_vip = True

# 1. Invocación y captura del retorno
coste_compra = calcular_precio_final(precio_objeto, usuario_es_vip)

if coste_compra == -1.0:
    print("❌ Error: El precio del objeto no es válido.")
else:
    print(f"💰 Precio base: {precio_objeto}€ | Final (VIP+IVA): {coste_compra}€")

    # 2. Uso del retorno dentro de un condicional
    if verificar_saldo_suficiente(saldo_jugador, coste_compra):
        saldo_restante = saldo_jugador - coste_compra
        print(f"✅ ¡Compra realizada! Saldo restante: {saldo_restante:.2f}€")
    else:
        print("⛔ Error: Saldo insuficiente en la cuenta.")

```

## 📝 Ejercicio de Diagnóstico

Analiza el siguiente fragmento de código e identifica los **3 errores de diseño, sintaxis o lógica** relacionados con el uso de `return`:

```python
def calcular_bono(puntos):
    if puntos > 100:
        return puntos * 0.20
        print("¡Bono especial aplicado!")
    else:
        print("Sin bono asignado.")

total_puntos = 150
bono_obtenido = calcular_bono(total_puntos)
puntos_finales = total_puntos + bono_obtenido

print(f"Puntos finales: {puntos_finales}")

```

### Respuestas de Diagnóstico:

1. **Código Inalcanzable (*Unreachable Code*):** La línea `print("¡Bono especial aplicado!")` se encuentra ubicada inmediatamente después del `return` dentro de la rama `if`. Jamás llegará a ejecutarse.
2. **Inconsistencia de Retorno e Incompatibilidad de Tipos:** Si `puntos` es menor o igual a 100, la rama `else` ejecuta un `print()` y no contiene ningún `return` explícito, devolviendo `None`. Al intentar ejecutar `total_puntos + bono_obtenido` fuera de la función, la operación `150 + None` lanzará un error crítico de tipo (`TypeError: unsupported operand type(s) for +: 'int' and 'NoneType'`).
3. **Ausencia de Retorno Unificado:** En lugar de imprimir dentro de la rama `else`, la función debería retornar `0` o `0.0` para garantizar que la función devuelva siempre un tipo de dato numérico operable.
