# 🔹 Unidad 2.11 - Práctica Evaluada: SOC Live Threat Stream Auditor

En esta actividad práctica, asumirás el rol de un especialista en **Respuesta a Incidentes (Incident Response)** dentro de un Centro de Operaciones de Seguridad (SOC). Tu tarea será desarrollar el núcleo de un sistema de monitorización automatizada que evalúe en tiempo real el estado de seguridad de los servidores de producción de la empresa.

Para ello, deberás procesar de manera controlada un flujo de datos dinámicos utilizando **iteradores manuales** en lugar de bucles `for` directos, garantizando un control granular del procesamiento en memoria y evitando excepciones en tiempo de ejecución.

---

## Objetivos de la Actividad

* Declarar y manipular **iteradores manuales** a partir de estructuras asociativas complejas.
* Utilizar la función `next()` con valores por defecto para controlar flujos sin lanzar excepciones `StopIteration`.
* Diseñar algoritmos de cálculo de riesgo combinando operaciones aritméticas y lógica condicional.
* Documentar el código según las normas **PEP 8** y las directrices de documentación **PEP 257 (Docstrings)**.

---

## Estructura de Datos Base

El estado en tiempo real de los servidores monitorizados se representará mediante un diccionario. La clave será el nombre identificador del servidor, y el valor asociado será una lista conteniendo tres métricas físicas obtenidas por los agentes de seguridad del sistema: `[conexiones_activas, intentos_fallidos_login, alertas_de_puertos]`.

Copia este diccionario en tu script como punto de partida:

```python
servidores_soc = {
    "SRV-Web": [120, 5, 0],       # [conexiones_activas, intentos_fallidos, alertas_puertos]
    "SRV-DB": [45, 0, 0],
    "SRV-Mail": [300, 15, 2],
    "SRV-Auth": [80, 55, 12],     # Anomalía grave: alto número de intentos de login y escaneo
    "SRV-Gateway": [1500, 1, 0]
}

```

## Requisitos del Programa

Escribe un script en Python llamado **`ra2_act11_auditor_soc.py`** (o `b2_11_auditor_soc.py`) que implemente la siguiente estructura modular:

### 1. Función de Cálculo de Riesgo

Crea una función llamada `calcular_score_amenaza(metricas)` que:

* Reciba una lista con las tres métricas del servidor: `[conexiones, fallos_login, alertas_puertos]`.
* Calcule un **Score de Amenaza** (número decimal) aplicando de forma estricta la siguiente fórmula de ponderación de riesgo:

$$\text{Score} = (\text{conexiones} \times 0.05) + (\text{fallos\_login} \times 2.0) + (\text{alertas\_puertos} \times 10.0)$$

* Retorne el valor del score calculado.

### 2. Función de Clasificación de Estado

Crea una función llamada `clasificar_estado_seguridad(score)` que:

* Reciba el score de amenaza como parámetro.
* Determine el estado según los siguientes rangos lógicos:
* Si el score es menor que `10.0`, devuelve el texto `"SEGURO"`.
* Si el score está entre `10.0` y `50.0` (inclusive ambos), devuelve el texto `"SOSPECHOSO"`.
* Si el score es mayor que `50.0`, devuelve el texto `"ALERTA CRITICA"`.



### 3. Programa Principal (Auditoría Manual con Iteradores)

En la sección principal del programa (`if __name__ == "__main__":`):

* Crea un **iterador** sobre las claves (nombres de los servidores) del diccionario `servidores_soc` usando la función `iter()`.
* Diseña un bucle continuo `while True` en el que extraigas el nombre del siguiente servidor usando de forma obligatoria la sintaxis de avance seguro: `next(iterador, None)`.
* Si el iterador devuelve `None`, el programa debe mostrar un mensaje informando del fin de la auditoría y romper el bucle limpiamente sin provocar excepciones.
* Para cada servidor extraído:
* Obtén sus métricas del diccionario.
* Llama a `calcular_score_amenaza()` para obtener su nivel numérico de riesgo.
* Llama a `clasificar_estado_seguridad()` para categorizar su salud.
* Muestra un reporte limpio alineando los nombres de los servidores y sus estados de forma profesional.

## Restricciones y Estilo (Normas PEP 8 / 257)

* **Prohibición de bucles `for` directos:** No se permite recorrer el diccionario de servidores de forma directa mediante un bucle `for`. Se debe usar el avance manual estructurado con `next(..., None)` y un bucle `while`.
* **Nomenclatura:** Todos los identificadores (funciones, variables) deben usar la convención `snake_case`. Las constantes lógicas irán en `UPPERCASE`.
* **Docstrings obligatorios:** Cada función (`calcular_score_amenaza` y `clasificar_estado_seguridad`) debe contener un **Docstring multilínea** descriptivo con comillas triples en la primera línea de su cuerpo.
