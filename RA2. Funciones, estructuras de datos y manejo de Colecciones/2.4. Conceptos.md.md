## 1. El Ámbito de las Variables y el Algoritmo LEGB

En Python, la visibilidad e inaccesibilidad de un identificador no es uniforme a lo largo del código. El **ámbito (*scope*)** define la región del programa donde un identificador (variable, función, clase) es directamente accesible dentro del espacio de nombres (*namespace*).

Para determinar a qué objeto hace referencia un nombre, el intérprete de Python evalúa los entornos siguiendo una secuencia jerárquica estricta denominada **Regla LEGB**:

```text
                  ┌─────────────────────────────────────────┐
                  │          B: Built-in Scope              │
                  │  (print, len, int, ValueError, ...)     │
                  │  ┌───────────────────────────────────┐  │
                  │  │        G: Global Scope            │  │
                  │  │  (Variables del script principal) │  │
                  │  │  ┌─────────────────────────────┐  │  │
                  │  │  │    E: Enclosing Scope       │  │  │
                  │  │  │ (Funciones anidadas/closures)│  │  │
                  │  │  │  ┌───────────────────────┐  │  │  │
                  │  │  │  │    L: Local Scope     │  │  │  │
                  │  │  │  │ (Interior de def)     │  │  │  │
                  │  │  │  └───────────────────────┘  │  │  │
                  │  │  └─────────────────────────────┘  │  │
                  │  └───────────────────────────────────┘  │
                  └─────────────────────────────────────────┘

```

1. **L - Local:** Identificadores declarados dentro del cuerpo de la función activa (incluyendo sus parámetros formalizados).
2. **E - Enclosing (Anidado):** Identificadores pertenecientes al ámbito de funciones envolventes o superiores (común en funciones anidadas y *closures*).
3. **G - Global:** Identificadores definidos en el nivel superior (*top-level*) del archivo o módulo `.py` en ejecución.
4. **B - Built-in:** Identificadores predefinidos en el lenguaje Python (`print`, `len`, `range`, `TypeError`, etc.).

Si el intérprete busca un identificador en el nivel **L** y no lo encuentra, escala secuencialmente a **E**, luego a **G** y finalmente a **B**. Si tras evaluar el nivel **B** la variable no existe, Python lanza la excepción `NameError`.

## 2. Variables Locales y Encapsulamiento

Una **variable local** es aquella creada dentro del marco de ejecución (*stack frame*) de una función.

* **Aislamiento y Ciclo de Vida:** Su memoria se asigna al invocar la función y se libera (mediante el recolector de basura) de forma automática cuando la función finaliza o ejecuta un `return`.
* **Inaccesibilidad Exterior:** Desde el ámbito global no es posible inspeccionar ni leer el estado de una variable local.

```python
def conectar_servicio():
    # Variable local: asignada exclusivamente al marco local de la función
    ip_servidor = "192.168.1.100"
    print(f"Conectado a: {ip_servidor}")


conectar_servicio()

# ❌ Intentar acceder a la variable fuera de su ámbito
# print(ip_servidor)  # Lanza NameError: name 'ip_servidor' is not defined

```

> **Ventaja Arquitectónica:** El aislamiento local permite declarar identificadores comunes (como `i`, `resultado` o `temporal`) en múltiples funciones de forma independiente, eliminando el riesgo de colisión de nombres (*name collision*).

## 3. Variables Globales y Sombreado (*Variable Shadowing*)

Una **variable global** se declara en la raíz del script, fuera de cualquier bloque de código delimitado por `def`.

### Lectura Directa

Cualquier función puede **leer** directamente el valor de una variable global sin necesidad de pasarla como parámetro:

```python
NOMBRE_PLATAFORMA = "SteamArcade"  # Variable global (Constante por convención)


def mostrar_bienvenida():
    # Acceso exitoso de lectura al ámbito Global (G)
    print(f"--- Sistema de Autenticación | {NOMBRE_PLATAFORMA} ---")


mostrar_bienvenida()

```

### El Fenómeno del Sombreado (*Shadowing*)

Si intentas reasignar o modificar una variable global desde el interior de una función mediante el operador de asignación (`=`), Python **no modifica la variable global**. En su lugar, crea explícitamente una **nueva variable local** dentro del marco de la función que tapona o "sombrea" a la variable global exterior durante la ejecución de dicho bloque.

```python
volumen_audio = 50  # Variable global


def ajustar_volumen():
    volumen_audio = 80  # ⚠️ Sombreado: crea una variable LOCAL 'volumen_audio'
    print(f"Volumen dentro de la función (Local): {volumen_audio}")


ajustar_volumen()  # Muestra: 80
print(f"Volumen fuera de la función (Global): {volumen_audio}")  # Muestra: 50

```

## 4. La Sentencia `global` y su Mecánica Interna

Cuando se requiere explícitamente que una función modifique de forma directa la referencia en el espacio de nombres global, se utiliza la palabra clave `global`.

Esta instrucción le indica formalmente al compilador de Python que cualquier asignación posterior sobre dicho identificador dentro de la función debe aplicarse a la variable del ámbito global (*Global Scope*), omitiendo la creación de una variable local.

```python
partida_en_pausa = False  # Variable global


def cambiar_estado_pausa():
    global partida_en_pausa  # Enlaza el identificador al ámbito global
    partida_en_pausa = True  # Modificación persistente sobre la variable global
    print("[SISTEMA]: Estado de la partida alterado.")


print(f"¿Pausado antes?: {partida_en_pausa}")  # False
cambiar_estado_pausa()
print(f"¿Pausado después?: {partida_en_pausa}")  # True

```

## 📊 5. Evaluación de Arquitectura: Por qué `global` es un Antipatrón

Aunque la sentencia `global` soluciona técnicamente el conflicto de escritura, en la ingeniería de software profesional se considera una **práctica desaconsejada (*antipattern*)**.

### Riesgos Principales:

1. **Efectos Secundarios Ocultos (*Side Effects*):** Una función que altera variables globales modifica el estado global del sistema de forma impredecible, complicando el seguimiento del código.
2. **Acoplamiento Fuerte (*High Coupling*):** La función deja de ser autónoma. Queda ligada a que el script declare exactamente los mismos nombres de variables globales fuera de ella.
3. **Pérdida de Pura Reutilización:** La función no puede ser exportada o reutilizada fácilmente en otros módulos.

---

### Comparativa de Diseños

| Criterio | Enfoque Acoplado (`global`) | Enfoque Pythónico Limpio (Parámetro + `return`) |
| --- | --- | --- |
| **Flujo de datos** | Implicito / Incurre en mutación global. | Explícito / A través de la firma e invocación. |
| **Reutilización** | Muy baja (depende del estado externo). | Totalmente modular e independiente. |
| **Facilidad de testeo** | Compleja (exige configurar el entorno global). | Directa (invocación con argumentos concretos). |

```python
# ❌ ENFOQUE DEBILES (Acoplado con 'global'):
puntos_jugador = 100


def sumar_puntos_malo(cantidad):
    global puntos_jugador
    puntos_jugador += cantidad


# ✅ ENFOQUE CANÓNICO PYTHONICO (Aislado, explícito y desacoplado):
def sumar_puntos_bueno(puntos_actuales, cantidad):
    """Calcula y devuelve la nueva puntuación sin modificar estado externo."""
    return puntos_actuales + cantidad


# El control del estado lo mantiene el flujo principal
puntos_jugador = 100
puntos_jugador = sumar_puntos_bueno(puntos_jugador, 50)  # Puntos vale 150

```

## 💻 6. Ejemplo Integrador Completo

El siguiente programa demuestra el manejo limpio del ámbito de variables dentro de un subsistema de salud y combate para un videojuego:

```python
"""
Módulo de cálculo de estado de salud para personajes RPG.
Demuestra la resolución del ámbito de variables sin recurrir al antipatrón 'global'.
"""

# --- CONSTANTES GLOBALES (Lectura estricta) ---
VIDA_MAXIMA_PERMITIDA = 200.0
TASA_REGENERACION_BASE = 0.05


def aplicar_paciencia_curativa(vida_actual, nivel_pocion):
    """Calcula la vida resultante tras aplicar una cura sin alterar variables globales.

    :param vida_actual: Cantidad actual de HP del personaje (float).
    :param nivel_pocion: Nivel del ítem consumible (int).
    :return: Nueva vida calculada limitada por la constante máxima (float).
    """
    # 'VIDA_MAXIMA_PERMITIDA' se lee desde el ámbito Global (G) por la regla LEGB
    recuperacion = (nivel_pocion * 10.0) + (vida_actual * TASA_REGENERACION_BASE)
    vida_calculada = vida_actual + recuperacion

    # Control local de límites (Guard clause)
    if vida_calculada > VIDA_MAXIMA_PERMITIDA:
        return VIDA_MAXIMA_PERMITIDA

    return round(vida_calculada, 2)


# --- PUNTO DE ENTRADA PRINCIPAL ---
hp_personaje = 120.0
pocion_equipada = 3

print(f"HP Inicial del personaje: {hp_personaje} HP")

# Actualización explícita del estado mediante retorno de función
hp_personaje = aplicar_paciencia_curativa(hp_personaje, pocion_equipada)

print(f"HP tras usar poción: {hp_personaje} HP")

```

## 📝 Ejercicio de Diagnóstico

Analiza el siguiente fragmento de código e identifica los **3 errores de diseño o ejecución** derivados del manejo del *scope*:

```python
monedas_oro = 50


def realizar_transaccion(coste):
    if monedas_oro >= coste:
        monedas_oro = monedas_oro - coste
        mensaje_exito = "Compra completada"
    else:
        mensaje_error = "Fondos insuficientes"

    return mensaje_exito


realizar_transaccion(30)
print(mensaje_exito)

```

### Respuestas de Diagnóstico:

1. **Excepción `UnboundLocalError`:** En la línea `monedas_oro = monedas_oro - coste`, Python detecta el operador de asignación `=` y cataloga `monedas_oro` como variable **local** dentro de toda la función. Sin embargo, al intentar evaluar el lado derecho (`monedas_oro - coste`), la variable local no ha sido inicializada previamente, lo que desencadena la excepción `UnboundLocalError: local variable 'monedas_oro' referenced before assignment`.
2. **Excepción `UnboundLocalError` o `UnboundLocalError/NameError` en retorno condicional:** Si `monedas_oro < coste` (rama `else`), la variable `mensaje_exito` nunca llega a crearse. La función intentará ejecutar `return mensaje_exito` al final, provocando una excepción `UnboundLocalError`.
3. **Excepción `NameError` en el flujo principal:** La instrucción final `print(mensaje_exito)` intenta acceder a `mensaje_exito` desde el ámbito global. Al ser una variable creada únicamente dentro del marco local de la función, el programa lanzará la excepción `NameError: name 'mensaje_exito' is not defined`.
