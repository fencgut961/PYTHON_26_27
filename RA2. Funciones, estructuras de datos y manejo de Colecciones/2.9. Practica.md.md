# 🔹 Práctica 2.9 - Cross-Incident Log Correlator & Threat Intelligence Synthesizer

En el ámbito de la ciberseguridad, los analistas de Respuesta a Incidentes (*Incident Response*) dentro de un Centro de Operaciones de Seguridad (SOC) reciben constantemente alertas y registros (*logs*) procedentes de múltiples sondas de red y servidores de forma aislada.

Para poder entender el alcance de una intrusión compleja, es obligatorio sincronizar cronológicamente estos flujos independientes de datos (marcas de tiempo, IPs de origen, puertos de destino y *payloads* detectados) en un único informe unificado. En esta práctica, programarás un correlacionador cruzado de seguridad utilizando la función integrada `zip()`.

---

## 🎯 Objetivos de la Actividad

* Aplicar la función integrada `zip()` para recorrer y unificar múltiples colecciones paralelas de forma limpia y eficiente.
* Comprender y aplicar el control automático de desajustes de longitud en colecciones utilizando `zip()`.
* Utilizar el desempaquetado de tuplas con el operador estrella (`zip(*...)`) para extraer y aislar datos de amenazas de red.
* Organizar y persistir los incidentes en un diccionario anidado local como base de datos en memoria para el SOC.
* Modularizar el programa en funciones parametrizadas independientes y documentadas según PEP 8 y PEP 257.

---

## 💻 El Reto: Correlacionador Cruzado de Seguridad

Tu empresa ha sufrido un intento de intrusión distribuido. Cuatro sondas independientes del SOC han exportado los siguientes logs en listas separadas durante el intervalo del incidente:

### 📊 Datos de Entrada de Referencia

```python
timestamps = ["14:22:05", "14:23:18", "14:25:40", "14:28:11", "14:30:00"]
source_ips = ["185.220.101.5", "192.168.1.15", "45.138.99.102", "10.0.0.8"]
target_ports = [3389, 80, 22, 443, 8080]
payloads = ["RDP Exploit Attempt", "Normal HTTP GET", "SSH Brute Force", "HTTPS Handshake", "WAF Blocked"]

```

> **Atención:** Las listas `timestamps`, `target_ports` y `payloads` contienen 5 elementos, pero la lista `source_ips` contiene solo 4 elementos debido a un fallo de red durante el volcado forense. Tu script debe manejar de forma automática este desajuste utilizando el comportamiento nativo de la función `zip()`.

---

## 🛠️ Instrucciones y Fases del Desarrollo

Debes crear un archivo ejecutable en Python (`ra2_act9_correlacionador_soc.py` / `b2_9_correlacionador_soc.py`) con la siguiente estructura modular:

### Fase 1: Función `correlacionar_logs(tiempos, ips, puertos, firmas)`

* Recibe las cuatro listas independientes como parámetros de entrada.
* Inicializa un diccionario vacío llamado `registro_incidentes`.
* Utiliza la función `zip()` para recorrer las cuatro listas simultáneamente en un único bucle `for`.
* Para cada iteración, genera un identificador secuencial como clave (ej: `"INC-001"`, `"INC-002"`, etc.).
* Asigna como valor de cada identificador un diccionario interno con las claves: `"Hora"`, `"IP"`, `"Puerto"`, `"Firma"` y `"Severidad"`.
* Calcula la `"Severidad"` según estas reglas de negocio:
* **CRÍTICA:** Si el puerto es `22` (SSH) o `3389` (RDP) **y** la firma contiene la cadena `"Exploit"` o `"Brute Force"`.
* **ALTA:** Si el puerto es `22` (SSH) o `3389` (RDP), pero no cumple la condición anterior.
* **MEDIA:** En cualquier otro caso.


* Retorna el diccionario `registro_incidentes` completo.

### Fase 2: Función `mostrar_reporte_soc(registro_incidentes)`

* Recibe el diccionario de incidentes correlacionados.
* Muestra en consola un reporte formateado y estructurado con los incidentes.
* Incluye un número de orden natural para el operador humano (empezando en `1`) junto al identificador del incidente.

### Fase 3: Función `aislar_ips_amenaza(registro_incidentes)`

* Recibe el diccionario de incidentes.
* Extrae todas las parejas de datos `(IP, Puerto)` de los incidentes registrados y las almacena en una lista de tuplas.
* Aplica el **desempaquetado estrella (`zip(*...)`)** sobre esta lista de tuplas para separar las IPs por un lado y los puertos por otro.
* Imprime y devuelve la tupla exclusiva con las IPs sospechosas aisladas para su bloqueo preventivo en el firewall.

### Fase 4: Bloque Principal e Interacción (`if __name__ == "__main__":`)

1. Define las cuatro listas de logs iniciales proporcionadas en los datos de referencia.
2. Invoca la función `correlacionar_logs` pasándole las listas como argumentos.
3. Imprime un mensaje informativo explicando que se han detectado desajustes de red y detallando cuántos incidentes se han logrado correlacionar de forma segura en base al tamaño de la lista de IPs.
4. Invoca la función `mostrar_reporte_soc` para renderizar el informe unificado en pantalla.
5. Invoca la función `aislar_ips_amenaza` para generar y visualizar la tupla de IPs aisladas.

## 📋 Requisitos de Estilo

1. **Guía PEP 8:** Todos los identificadores de variables y funciones deben estar escritos en minúsculas con guiones bajos (`snake_case`). Las constantes globales deben escribirse en mayúsculas (`UPPERCASE`).
2. **Documentación PEP 257:** Cada función debe incluir obligatoriamente un **Docstring multilínea** (`"""`) especificando su propósito, parámetros y valor de retorno.
3. **Calidad de código:** Mantener líneas de código limpias, formateadas mediante *f-strings* y sin comentarios redundantes.

## 🚀 Entrega y Nomenclatura

* **Nombre obligatorio del archivo:** Guarda la solución como **`ra2_act9_correlacionador_soc.py`** (o `b2_9_correlacionador_soc.py`).
* **Verificación de restricciones:** Asegúrate de que el procesamiento simultáneo emplee `zip()`, que el aislamiento de datos utilice `zip(*...)` y que no se produzcan errores por desbordamiento de índice (`IndexError`).
