## 🧱 1. La Necesidad de la Modularización

A medida que aumenta la complejidad de un sistema informático, la **programación monolítica** (escribir todas las instrucciones en un único bloque secuencial de arriba a abajo) se vuelve ineficiente e inmanejable.

La **modularización** es un principio de diseño de software que divide un programa en módulos o subprogramas autónomos. La unidad fundamental de modularización en Python es la **función**.

### Principios clave del uso de funciones:

* **Reutilización de código (Principio DRY - *Don't Repeat Yourself*):** Evita la duplicación. Una tarea se codifica una sola vez y se invoca múltiples veces.
* **Mantenibilidad y aislamiento de fallos:** Si se detecta un error o cambia una regla de negocio, la modificación se realiza únicamente en la función encargada de esa tarea.
* **Abstracción:** El programador que invoca una función necesita conocer **qué hace** y qué datos requiere, sin necesidad de preocuparse por **cómo** procesa internamente la información.
* **Testabilidad:** Facilita la creación de pruebas unitarias (*unit testing*) para validar cada componente de forma aislada.

---

## 📊 Comparativa: Programación Monolítica vs. Modular

| Criterio | Programación Monolítica | Programación Modular (Funciones) |
| --- | --- | --- |
| **Estructura** | Un único bloque de código secuencial continuo. | Bloques independientes divididos por responsabilidades. |
| **Duplicación** | Código repetido ante la misma necesidad operativa. | Reutilización de bloques mediante llamadas/invocaciones. |
| **Localización de Errores** | Compleja; una falla afecta todo el script global. | Aislada en el cuerpo de la función correspondiente. |
| **Lectura del código** | Densa, con alto acoplamiento de variables. | Descriptiva, basada en nombres de procedimientos. |

## ⚙️ 2. Declaración de Funciones: La Sintaxis `def`

La declaración de una función crea un objeto de tipo función en la memoria de Python y le asigna un identificador.

```text
  ┌── Palabra reservada
  │     ┌── Identificador (snake_case)
  │     │                       ┌── Paréntesis obligatorios
  │     │                       │  ┌── Dos puntos finales
  ▼     ▼                       ▼  ▼
 def nombre_de_la_funcion():
 █ █ █ █ """Docstring explicativo."""
 █ █ █ █ instruccion_1
 █ █ █ █ instruccion_2
 ▲
 └── Indentación obligatoria (4 espacios)

```

### Reglas sintácticas estrictas:

1. **La palabra clave `def`:** Notifica al intérprete el inicio de una definición de función.
2. **Identificador (`snake_case`):** Debe ser descriptivo, estar en minúsculas y separar palabras con guiones bajos (ej. `mostrar_estado_red`, `calcular_descuento`). Debe cumplir con las reglas de identificadores válidos (sin caracteres especiales ni inicio numérico).
3. **Paréntesis `()`:** Delimitan la cabecera de la función. En funciones básicas, la lista de parámetros puede estar vacía, pero los paréntesis son sintácticamente obligatorios.
4. **Dos puntos `:`:** Cierran la cabecera e inician el bloque condicional del cuerpo.
5. **Indentación de bloque (4 espacios):** Define qué instrucciones forman parte de la función. Al eliminar la indentación, Python asume que la función ha finalizado.

## 📚 3. Documentación Formal mediante Docstrings (PEP 257)

Un **Docstring** es una cadena literal colocada como la primera instrucción dentro de una función, delimitada por comillas triples (`""" ... """`). Su función es documentar el propósito del procedimiento.

```python
def emitir_alerta_seguridad():
    """Imprime una advertencia de intento de acceso no autorizado."""
    print("⚠️  ALERTA: Se ha detectado un intento de acceso inválido.")

```

### Diferencia entre Comentarios (`#`) y Docstrings (`"""`):

* **Comentarios (`#`):** Explicaciones dirigidas al desarrollador sobre cómo funciona una línea de código específica. Son ignorados por completo durante el análisis sintáctico.
* **Docstrings (`"""`):** Se asocian al objeto función en tiempo de ejecución. Permiten la **introspección** mediante herramientas de autocompletado en IDEs (IntelliJ IDEA, PyCharm), la función interna `help()` o accediendo al atributo especial `__doc__`.

```python
# Muestra el docstring formateado en la consola interactiva
help(emitir_alerta_seguridad)

# Imprime directamente el atributo interno del objeto
print(emitir_alerta_seguridad.__doc__)

```

## 🔄 4. Flujo de Ejecución e Invocación

Definir una función **no ejecuta su código**; únicamente la compila en memoria de código (*bytecode*). Para ejecutar el bloque interno, la función debe ser **invocada** (llamada) escribiendo su nombre seguido de paréntesis desde un punto activo del programa.

```python
# 1. Fase de definición (se registra en memoria, no hay salida por consola)
def cargar_texturas():
    """Simula la carga de recursos gráficos."""
    print("🎨 Cargando texturas del entorno...")

# 2. Fase de invocación (se transfiere el control a la función)
cargar_texturas()  # Imprime: 🎨 Cargando texturas del entorno...
cargar_texturas()  # Se ejecuta nuevamente

```

### El orden importa: Prevención de `NameError`

Python es un lenguaje interpretado que lee el script línea por línea desde arriba hacia abajo. Es **obligatorio definir una función antes de llamarla**.

```python
# ❌ ERROR EN TIEMPO DE EJECUCIÓN
iniciar_sistema()  # NameError: name 'iniciar_sistema' is not defined

def iniciar_sistema():
    """Inicia los servicios base."""
    print("Iniciando...")

```

### Estructura estándar de un script Python (PEP 8):

1. **Docstring del módulo:** Explicación global del archivo.
2. **Sentencias `import`:** Importación de librerías o módulos.
3. **Constantes globales:** Declaradas en `UPPERCASE`.
4. **Definiciones de funciones:** Todas las funciones del módulo con sus respectivos docstrings.
5. **Código principal / Punto de entrada:** Bloque desde donde se realizan las invocaciones en secuencia.

## 🔒 5. Ámbitos de Memoria (*Scope*) y Variables Locales

Toda variable asignada dentro del cuerpo de una función se crea en un marco de memoria temporal denominado **Ámbito Local (*Local Scope*)**.

```python
def registrar_puntuacion():
    """Registra la puntuación alcanzada de forma local."""
    puntos_partida = 1500  # Variable local
    print(f"Puntuación registrada: {puntos_partida}")

# Invocación válida de la función
registrar_puntuacion()

# ❌ ERROR: Acceso fuera de ámbito
# print(puntos_partida)  # NameError: name 'puntos_partida' is not defined

```

### Ciclo de vida de una variable local:

1. **Creación:** La variable nace en el momento exacto en que la línea de asignación dentro de la función es interpretada.
2. **Persistencia:** Solo vive mientras el puntero de ejecución permanezca dentro del cuerpo de la función.
3. **Destrucción:** Al finalizar la función (llegar a la última línea o encontrar un retorno), el marco de pila (*stack frame*) de la función se destruye y la memoria asociada a las variables locales se libera automáticamente.

## 📐 6. Análisis de Caso: Traza de Ejecución y Ámbito Local

Observa detenidamente la traza de ejecución del siguiente script:

```python
# [Línea 1] Definición de constante global
ESTADO_SISTEMA = "OPERATIVO"

# [Línea 3] Definición de función
def auditar_sistema():
    """Muestra el estado global y una métrica local."""
    latencia_ms = 12  # Variable local
    print(f"Sistema: {ESTADO_SISTEMA} | Latencia: {latencia_ms}ms")

# [Línea 8] Inicio de ejecución principal
print("--- INICIANDO AUDITORÍA ---")
auditar_sistema()  # Salto de la ejecución a la Línea 4
print("--- AUDITORÍA FINALIZADA ---")

```

### Traza paso a paso:

1. El intérprete registra `ESTADO_SISTEMA` en el ámbito global.
2. Salta las líneas 3 a 6 (almacena la función `auditar_sistema` en memoria sin ejecutar su cuerpo).
3. Llega a la Línea 8 e imprime: `--- INICIANDO AUDITORÍA ---`.
4. En la Línea 9 encuentra la llamada `auditar_sistema()`. El control salta a la Línea 4.
5. Se crea el marco local, se asigna `latencia_ms = 12` e imprime el mensaje en consola.
6. La función termina; la variable local `latencia_ms` es destruida de la memoria.
7. El control retorna a la Línea 10 e imprime: `--- AUDITORÍA FINALIZADA ---`.

## 💻 7. Ejemplo de Código Integrador

El siguiente archivo muestra el patrón de diseño estructurado para la inicialización modular de un sistema:

```python
"""
Módulo de arranque de terminales arcade.
Aplica modularización básica, docstrings PEP 257 y convenciones PEP 8.
"""

# --- CONSTANTES GLOBALES ---
NOMBRE_CONSOLA = "SteamArcade Terminal"
VERSION_FIRMWARE = "1.0.4"


# --- DEFINICIÓN DE FUNCIONES ---
def mostrar_bienvenida():
    """Muestra la cabecera oficial de la consola en pantalla."""
    print("========================================")
    print(f"   {NOMBRE_CONSOLA} - v{VERSION_FIRMWARE}")
    print("========================================")


def diagnosticar_perifericos():
    """Verifica el estado de los controles locales del gabinete."""
    palanca_ok = True
    botones_activos = 6
    print(f"[HW] Joystick: {palanca_ok} | Botones detectados: {botones_activos}")


def conectar_servidor():
    """Simula el saludo inicial con la red de autenticación."""
    ip_gateway = "10.0.0.1"
    print(f"[NET] Enlazando con pasarela en {ip_gateway}...")


# --- PUNTO DE ENTRADA PRINCIPAL ---
print("Iniciando secuencia de arranque...")
mostrar_bienvenida()
diagnosticar_perifericos()
conectar_servidor()
print("Proceso de arranque completado con éxito.")

```

## 📝 Ejercicio de Diagnóstico

Analiza el siguiente código e identifica los **3 errores** de sintaxis/lógica relacionados con la definición e invocación de funciones:

```python
def iniciar_sesion():
"""Inicia el proceso de login."""
    usuario_actual = "Admin"
    print(f"Bienvenido, {usuario_actual}")

iniciar_sesion()
print(usuario_actual)

cerrar_sesion()

def cerrar_sesion():
    print("Sesión cerrada.")

```

### Respuestas de Diagnóstico:

1. **Error de Indentación (`IndentationError`):** El docstring `"""Inicia el proceso de login."""` dentro de `iniciar_sesion()` no posee la indentación de 4 espacios requerida.
2. **Error de Ámbito Local (`NameError`):** La línea `print(usuario_actual)` intenta acceder a una variable que solo existe dentro del ámbito local de `iniciar_sesion()`.
3. **Error de Pre-declaración (`NameError`):** La función `cerrar_sesion()` es invocada **antes** de haber sido definida en el archivo.
