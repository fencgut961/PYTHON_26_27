## 1. Parámetros vs. Argumentos: La Anatomía de la Comunicación

Para construir software modular avanzado, es imprescindible distinguir el rol de las variables en la cabecera de una función respecto a los datos suministrados durante la invocación:

* **Parámetro:** Variable formal declarada dentro de los paréntesis de la cabecera `def`. Actúa como un *slot* o identificador local dentro del marco de pila de la función.
* **Argumento:** Objeto o valor concreto transferido a la función en la línea de invocación.

```text
               DECLARACIÓN (Cabecera)
          def configurar_avatar(nombre, nivel):
                                  ▲       ▲
                                  │       └─ Parámetro 2
                                  └───────── Parámetro 1

               INVOCACIÓN (Llamada)
          configurar_avatar("Aria", 15)
                               ▲     ▲
                               │     └─ Argumento 2 (int)
                               └─────── Argumento 1 (str)

```

```python
def configurar_avatar(nombre, nivel):
    """Carga la configuración base de un personaje jugable."""
    print(f"🎮 Avatar: {nombre} | Nivel de inicio: {nivel}")

# Invocación pasando valores físicos (Argumentos)
configurar_avatar("Aria", 15)

```

## 2. Clasificación y Mecanismos de Paso de Argumentos

Python ofrece tres mecanismos principales para mapear argumentos a parámetros durante la invocación.

### A. Parámetros Posicionales

Son aquellos cuyo mapeo se realiza de forma estrictamente secuencial: el primer argumento se asigna al primer parámetro, el segundo al segundo, y así sucesivamente.

```python
def asignar_habilidad(clase, habilidad_definitiva):
    """Muestra la habilidad asociada a una clase RPG."""
    print(f"Clase: {clase} -> Habilidad: {habilidad_definitiva}")

# Invocación correcta por posición
asignar_habilidad("Mago", "Bola de Fuego")
# Salida: Clase: Mago -> Habilidad: Bola de Fuego

# Invocación incorrecta por alteración del orden
asignar_habilidad("Bola de Fuego", "Mago")
# Salida: Clase: Bola de Fuego -> Habilidad: Mago (Inconsistencia lógica)

```

> **Riesgo:** Si una función requiere múltiples parámetros posicionales, alterar inadvertidamente el orden produce errores lógicos o excepciones de tipo (`TypeError`) difíciles de depurar.

### B. Parámetros con Valores por Defecto (Argumentos Opcionales)

Permiten asignar un valor predeterminado a un parámetro en la firma de la función. Si el invocador omite dicho argumento, la función utiliza el valor por defecto.

```python
def conectar_servidor(usuario, puerto=8080, encriptado=True):
    """Simula el enlace a un servidor de juegos con parámetros opcionales."""
    print(f"Conectando '{usuario}' | Puerto: {puerto} | SSL: {encriptado}")

# Se usan los valores por defecto para 'puerto' y 'encriptado'
conectar_servidor("jugador_1")

# Se sobrescribe el valor de 'puerto' manteniéndose 'encriptado' por defecto
conectar_servidor("admin_retro", 443)

```

⚠️ **Regla de Sintaxis Obligatoria (PEP 8):** Los parámetros con valor por defecto deben situarse obligatoriamente **después** de todos los parámetros posicionales sin valor por defecto. En caso contrario, el intérprete lanzará un `SyntaxError`.

```python
# ❌ INCORRECTO: Produce SyntaxError: non-default argument follows default argument
def registrar_item(rareza="Común", nombre):
    pass

# ✅ CORRECTO: Los parámetros obligatorios preceden a los opcionales
def registrar_item(nombre, rareza="Común"):
    pass

```

### C. Argumentos Nombrados (*Keyword Arguments*)

Permiten asociar explícitamente el valor asignado al nombre del parámetro durante la llamada, utilizando la sintaxis `nombre_parametro = valor`.

```python
def crear_partida(mapa, max_jugadores, baneo_activo):
    """Configura los parámetros de una sala multijugador."""
    print(f"Mapa: {mapa} | Capacidad: {max_jugadores} | Ban: {baneo_activo}")

# Invocación explícita desordenada: totalmente válida
crear_partida(baneo_activo=True, mapa="Aldea Oscura", max_jugadores=4)

```

#### Ventajas clave:

1. **Invariancia del orden:** Se rompe la dependencia de la posición física de los argumentos.
2. **Autodocumentación:** La llamada expresa claramente el significado de cada dato transmitido.

## 📊 3. Comparativa de Mecanismos de Parámetros

| Mecanismo | Sintaxis en Declaración / Invocación | Ventaja Principal | Limitación / Riesgo |
| --- | --- | --- | --- |
| **Posicional** | `def f(a, b)`<br>

<br>`f(1, 2)` | Sintaxis concisa y directa. | Alta sensibilidad al orden de los argumentos. |
| **Por Defecto** | `def f(a, b=10)`<br>

<br>`f(5)` | Flexibilidad; reduce la redundancia en llamadas comunes. | Debe posicionarse siempre al final de la cabecera. |
| **Nombrado (*Keyword*)** | `def f(a, b)`<br>

<br>`f(b=2, a=1)` | Total claridad semántica e independencia del orden. | Mayor verbosidad en la línea de invocación. |

## ⚠️ 4. Antipatrones y Trampas Comunes

### 1. El Bug del Argumento Por Defecto Mutable (*Mutable Default Argument*)

Un error crítico en Python ocurre al utilizar objetos mutables (como listas o diccionarios) como valores por defecto. Python evalúa el valor por defecto **una sola vez** cuando la función se define, no en cada invocación.

```python
# ❌ ANTIPATRÓN: La lista por defecto es compartida entre todas las llamadas
def agregar_equipo(objeto, inventario=[]):
    inventario.append(objeto)
    return inventario

# Primera llamada
print(agregar_equipo("Espada"))     # Salida: ['Espada']

# Segunda llamada (reutiliza la misma lista en memoria)
print(agregar_equipo("Escudo"))     # Salida: ['Espada', 'Escudo']  ⚠️ BUG

```

#### Solución Canónica (PEP 8):

Utilizar `None` como centinela e inicializar el objeto dentro del cuerpo local de la función:

```python
# ✅ SOLUCIÓN CORRECTA
def agregar_equipo(objeto, inventario=None):
    """Agrega un objeto a un inventario sin compartir estado entre llamadas."""
    if inventario is None:
        inventario = []
    inventario.append(objeto)
    print(f"Inventario actualizado: {inventario}")

```

### 2. Mezcla de Argumentos Posicionales y Nombrados

Si en una misma invocación se combinan argumentos posicionales y nombrados, **todos los argumentos posicionales deben ir antes** de los argumentos nombrados.

```python
def guardar_record(usuario, puntos, juego):
    print(f"{usuario} - {puntos} pts en {juego}")

# ❌ INCORRECTO: Argumento posicional tras uno nombrado
# guardar_record(usuario="Gamer1", 5000, "Space Invaders")
# SyntaxError: positional argument follows keyword argument

# ✅ CORRECTO: Posicionales primero, nombrados después
guardar_record("Gamer1", juego="Space Invaders", puntos=5000)

```

## 💻 6. Ejemplo Integrador Completo

El siguiente script aplica modularización avanzada mediante parámetros posicionales, opcionales y nombrados dentro del contexto del sistema **SteamArcade**:

```python
"""
Módulo de gestión de partidas para SteamArcade.
Demuestra el uso avanzado de parámetros y manejo de argumentos por defecto.
"""

def mostrar_cabecera_sala(nombre_sala, region="EU-West"):
    """Imprime el banner oficial de la sala de juego."""
    print("========================================")
    print(f" SERVIDOR: {nombre_sala} [{region}]")
    print("========================================")


def registrar_jugador(nombre, nivel=1, rol="Combatiente", VIP=False):
    """Registra un nuevo jugador en la sesión activa con atributos parametrizados.

    :param nombre: Identificador del jugador (str).
    :param nivel: Nivel de experiencia inicial (int).
    :param rol: Clase asignada en el juego (str).
    :param VIP: Estado de suscripción especial (bool).
    """
    estado_vip = "⭐ VIP" if VIP else "Estándar"
    print(f"[NUEVO JUGADOR] {nombre} | Nivel: {nivel} | Rol: {rol} | {estado_vip}")


# --- EJECUCIÓN PRINCIPAL ---
# 1. Llamada combinando valor por defecto y especificación opcional
mostrar_cabecera_sala("Arcade-Retro-01")

# 2. Llamada usando solo argumentos posicionales
registrar_jugador("ShadowKnight", 12, "Asesino", True)

# 3. Llamada haciendo uso de valores por defecto
registrar_jugador("PrinceOfPersia")

# 4. Llamada combinando argumentos posicionales y nombrados desordenados
registrar_jugador("MageMaster", VIP=True, rol="Hechicero", nivel=50)

```

## 📝 Ejercicio de Diagnóstico

Analiza el siguiente fragmento de código e identifica los **3 errores de sintaxis y/o lógica** presentes:

```python
def configurar_graficos(resolucion="1080p", fps, v_sync=True):
    print(f"Config: {resolucion} @ {fps}FPS | VSync: {v_sync}")

def registrar_log(mensaje, etiquetas=[]):
    etiquetas.append(mensaje)
    print(f"Log: {etiquetas}")

configurar_graficos(60, resolucion="1440p")

```

### Respuestas de Diagnóstico:

1. **Error de Firma/Sintaxis (`SyntaxError`):** En `configurar_graficos`, el parámetro por defecto `resolucion="1080p"` precede al parámetro posicional obligatorio `fps`. Los parámetros sin valor por defecto deben ir primero.
2. **Antipatrón de Parámetro Mutable:** En `registrar_log`, la lista vacía `etiquetas=[]` se mantendrá en memoria y compartirá datos entre sucesivas invocaciones. Debe usarse `etiquetas=None`.
3. **Error de Invocación (`TypeError`):** En `configurar_graficos(60, resolucion="1440p")`, se pasa `60` como primer argumento posicional (asignado a `resolucion`) y luego se intenta asignar nuevamente `resolucion="1440p"` como nombrado, dejando a `fps` sin valor o duplicando el parámetro `resolucion`.
