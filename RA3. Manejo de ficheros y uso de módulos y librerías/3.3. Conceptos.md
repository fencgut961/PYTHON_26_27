## 1. Creación de un Módulo Personalizado

Cualquier archivo de Python con extensión `.py` es, por definición, un **módulo** que puede ser importado y reutilizado por otros scripts ubicados dentro del mismo proyecto.

### Ejemplo de implementación paso a paso

Imaginemos un entorno de ciberseguridad donde se separa la lógica de procesamiento de subredes de la lógica de presentación del programa.

#### Paso 1: Módulo de utilidades de red (`redes_util.py`)

```python
# redes_util.py
"""Módulo corporativo para operaciones de análisis de red."""


def calcular_subredes(hosts_necesarios: int) -> int:
    """Calcula el número óptimo de subredes necesarias en base a los hosts requeridos.

    :param hosts_necesarios: Cantidad de hosts a direccionar
    :return: Número total de subredes reservadas
    """
    if hosts_necesarios <= 0:
        return 0
    return hosts_necesarios * 2

```

#### Paso 2: Importación y consumo desde el archivo principal (`main.py`)

```python
# main.py
"""Punto de entrada principal de la aplicación."""

import redes_util

hosts = 120
subredes_disponibles = redes_util.calcular_subredes(hosts)
print(f"Para {hosts} hosts, se han reservado {subredes_disponibles} subredes.")

```

---

### Variaciones de Importación de Módulos Propios

Al igual que con la librería estándar, se pueden aplicar distintas sintaxis de importación:

```python
# Importación con alias abreviado
import redes_util as net

print(net.calcular_subredes(50))

# Importación directa de la función específica
from redes_util import calcular_subredes

print(calcular_subredes(30))

```

## 2. Paquetes en Python y el Rol del Fichero `__init__.py`

Cuando una aplicación crece, mantener decenas de módulos en el directorio raíz genera desorden. La solución es agruparlos en **paquetes** (carpetas del sistema de archivos con propósito específico).

Un paquete en Python es una carpeta que contiene uno o más módulos y, por estándar profesional, un archivo especial de inicialización denominado **`__init__.py`**.

```text
mi_herramienta/
│── main.py
│── seguridad/                 <-- PAQUETE
│   ├── __init__.py           <-- Archivo de inicialización del paquete
│   ├── firewall.py           <-- Módulo del paquete
│   └── cifrado.py            <-- Módulo del paquete

```

### Funciones esenciales de `__init__.py`

1. **Identificación del Paquete:** Declara formalmente ante el intérprete de Python que la carpeta es un paquete importable.
2. **Inicialización:** Se ejecuta automáticamente la primera vez que se importa el paquete, permitiendo cargar configuraciones o validar dependencias.
3. **Control de la API Pública:** Expone de forma directa las funciones o clases principales de los submódulos, simplificando la sintaxis para el usuario final del paquete.

---

## 3. Carpetas Normales frente a Paquetes (PEP 420)

Desde **Python 3.3** (especificación **PEP 420 - Namespace Packages**), no es estrictamente obligatorio incluir `__init__.py` para importar módulos contenidos dentro de una carpeta. Sin embargo, omitirlo se considera una mala práctica en entornos de producción.

| Característica | Carpeta sin `__init__.py` (PEP 420) | Paquete con `__init__.py` (Estándar) |
| --- | --- | --- |
| **Compatibilidad** | Inconsistente según el entorno o el IDE (IntelliJ, VSCode). | ✅ 100% predecible y portátil en cualquier entorno. |
| **Código de Inicialización** | ❌ No permite ejecutar lógica al importar la carpeta. | ✅ Permite cargar configuraciones e inicializar variables. |
| **Exportación Limpia (API)** | ❌ Obliga a importar especificando toda la ruta física. | ✅ Permite simplificar las llamadas mediante importaciones internas. |
| **Uso Recomendado** | Casos muy específicos de librerías distribuidas masivas. | ✅ Estándar obligatorio en proyectos corporativos y educativos. |

---

### Simplificación de la API Pública mediante `__init__.py`

#### Configuración de `seguridad/firewall.py`

```python
# seguridad/firewall.py
def bloquear_ip(ip: str) -> str:
    return f"IP {ip} bloqueada con éxito en el cortafuegos."

```

#### Configuración de `seguridad/__init__.py`

```python
# seguridad/__init__.py
# Exposición de la función hacia el nivel superior del paquete
from .firewall import bloquear_ip

```

#### Llamada directa desde `main.py`

```python
# main.py
import seguridad

# Invocación limpia directamente desde la API del paquete
resultado = seguridad.bloquear_ip("195.12.33.4")
print(resultado)

```

> **Ventaja:** Si no se utilizara `__init__.py`, se debería escribir `import seguridad.firewall` y llamarlo con `seguridad.firewall.bloquear_ip()`, exponiendo detalles de la estructura interna de carpetas.

## 4. Guía de Organización de Proyectos Complejos

Un proyecto profesional debe separar sus responsabilidades en capas claras y modulares.

### Estructura de directorio recomendada

```text
gestor_incidencias/
│
├── main.py                   # Punto de entrada unificado (orquestación del menú y flujo)
│
├── bases_datos/              # Paquete para la persistencia y lectura de datos
│   ├── __init__.py
│   └── lector_logs.py        # Módulo de procesamiento de ficheros .log
│
├── seguridad/                # Paquete de control y mitigación de amenazas
│   ├── __init__.py
│   ├── firewall.py           # Módulo para bloqueo de direcciones IP
│   └── cifrado.py            # Módulo para generación de hashes y firmas
│
├── utils/                    # Paquete con utilidades de soporte genérico
│   ├── __init__.py
│   └── formateadores.py      # Módulo para formateo estético de salidas por pantalla
│
└── README.md                 # Documentación técnica, dependencias e instalación

```

### Reglas de oro para la arquitectura

1. **Punto de entrada único (`main.py`):** No debe contener lógica de procesamiento compleja. Su única responsabilidad es importar los paquetes, mostrar la interfaz de usuario (por ejemplo, con `match-case`) y coordinar la ejecución.
2. **Prohibición de `sys.path.append()`:** Modificar manualmente las rutas del sistema dinámicamente genera código frágil e inexportable. Debe usarse la estructura jerárquica nativa de paquetes e importaciones relativas (`from .modulo import ...`).
3. **Encapsulamiento de Dependencias:** Cada paquete debe resolver un dominio concreto del problema, minimizando las dependencias acopladas entre paquetes distintos.

## 💻 5. Ejemplo Integrador Completo

Simulación de un sistema modular completo donde `main.py` interactúa con la API del paquete `seguridad`:

```python
"""
Punto de entrada principal: main.py
Coordina los componentes modulares del sistema de gestión de incidentes.
"""

# Simulación de la estructura del paquete seguridad
class PaqueteSeguridadSimulado:
    @staticmethod
    def bloquear_ip(ip: str) -> str:
        return f"[FIREWALL] Regla aplicada: Denegar tráfico entrante desde {ip}"

    @staticmethod
    def generar_hash(datos: str) -> str:
        import hashlib
        return hashlib.sha256(datos.encode("utf-8")).hexdigest()[:16]


def ejecutar_auditoria_sistema() -> None:
    """Orquesta las verificaciones de seguridad invocando las capas del paquete."""
    seguridad = PaqueteSeguridadSimulado()
    
    ip_sospechosa = "185.220.101.5"
    log_cadena = "2026-09-08 14:00:00 UNAUTHORIZED ACCESS ATTEMPT"

    print("=== INICIANDO PROTOCOLO DE MITIGACIÓN ===")
    
    # 1. Bloqueo mediante módulo de cortafuegos
    reporte_bloqueo = seguridad.bloquear_ip(ip_sospechosa)
    print(reporte_bloqueo)

    # 2. Generación de firma mediante módulo de cifrado
    firma_registro = seguridad.generar_hash(log_cadena)
    print(f"[CIFRADO] Hash de integridad generado: {firma_registro}")


# --- EJECUCIÓN PRINCIPAL ---
if __name__ == "__main__":
    ejecutar_auditoria_sistema()

```

## 📝 6. Ejercicio de Diagnóstico

Analiza los siguientes **3 errores de diseño y arquitectura** en un proyecto modular:

```python
# Tarea A: Mal uso de sys.path para forzar importaciones entre carpetas
import sys

sys.path.append("C:/Usuarios/admin/proyecto/seguridad")
import firewall

# Tarea B: Lógica de negocio pesada escrita directamente dentro de __init__.py
# Contenido de: seguridad/__init__.py
import os
import requests

def escanear_red_completa_y_guardar_db():
    # 300 líneas de código haciendo peticiones de red y escrituras en disco
    pass

# Tarea C: Importación circular entre dos módulos del mismo paquete
# Contenido de: seguridad/firewall.py
from .cifrado import firmar_regla

# Contenido de: seguridad/cifrado.py
from .firewall import validar_ip

```

### 💡 Respuestas de Diagnóstico

1. 🚨 **Ruta Absoluta Rígida e Inexportable (Tarea A):** Utilizar `sys.path.append()` con una ruta absoluta (`C:/Usuarios/...`) romperá la aplicación en cualquier otro ordenador o sistema operativo. La solución correcta es convertir la carpeta en un paquete con `__init__.py` y usar importaciones relativas o ejecutar el script desde la raíz del proyecto.
2. ⚠️ **Violación del Principio de Responsabilidad de `__init__.py` (Tarea B):** El archivo `__init__.py` debe ser ligero y limitarse a exponer funciones, inicializar configuraciones básicas o definir `__all__`. Colocar lógica pesada de 300 líneas dentro de `__init__.py` dificulta el mantenimiento y ralentiza la importación de cualquier submódulo del paquete.
3. ❌ **Importación Circular (*Circular Import*) (Tarea C):** `firewall.py` intenta importar a `cifrado.py` mientras que `cifrado.py` simultáneamente intenta importar a `firewall.py`. Esto genera un bloqueo mutuo al cargar los archivos, lanzando un `ImportError: cannot import name ...`. Debe rediseñarse el código para extraer la funcionalidad compartida a un tercer módulo auxiliar (ej. `utils.py`) o importar dentro de la función que lo necesite.
